# TalosDeck — Панель управления кластером Talos Linux & Kubernetes

**TalosDeck** — это открытый self-hosted веб-интерфейс (альтернатива коммерческому Sidero Omni) для комплексного управления, мониторинга, обслуживания и траблшутинга нод под управлением **Talos Linux** и работающего поверх них кластера **Kubernetes**.

Приложение скомпилировано в единый легковесный статический бинарник на **Go**, в который через `go:embed` вкомпилирован SPA-фронтенд на **Vue 3 + Vite + Tailwind CSS**. Оно напрямую взаимодействует с нодами через безопасный mTLS gRPC API Talos и Kubernetes API.

              │                              │

┌───────────────────────────┐  ┌───────────────────────────┐

└───────────────────────────┘  └───────────────────────────┘

- **Backend**: Go (веб-фреймворк Fiber)
  - Официальный Talos Go SDK (`github.com/siderolabs/talos/pkg/machinery`)
  - Официальный Kubernetes client-go (`k8s.io/client-go`)
  - Интеграция с Proxmox VE REST API
- **Frontend**: Vue 3 (Composition API) + TypeScript + Tailwind CSS + Lucide Icons + Vite
- **Хранилище данных**: SQLite / плоские файлы для аудита и бэкапов в `/app/data` (PVC)
- **Безопасность**:
  - Запуск в контейнере под непривилегированным пользователем `talosdeck:talosdeck` (UID/GID 1000)
  - Нативные пробы доступности `/healthz` (Liveness) и `/readyz` (Readiness с проверкой связи с нодами)
  - Аутентификация: OIDC (Keycloak) и локальная аутентификация

## 2. Реализованный функционал (Backend & Модули)

### 2.1. Управление и обнаружение нод (`internal/talos`)
- **Автодискавери нод кластера (`discovery.go`)**:
  - Опрос всех участников кластера через gRPC.
  - Определение роли каждой ноды (`controlplane`, `worker`).
  - Получение версий ядра Talos, ОС и версии Kubernetes.
  - Мониторинг системных ресурсов нод: утилизация CPU, оперативной памяти, использование дисковых разделов.
  - Определение статуса сетевых интерфейсов и IP-адресов.
- **Управление питанием и жизненным циклом (`node_ops.go`)**:
  - `Reboot`: безопасная одиночная перезагрузка конкретной ноды.
  - `Shutdown`: выключение ноды через API Talos.
  - `Maintenance Mode`: перевод ноды в режим обслуживания.
  - `Cordon / Uncordon`: запрет/разрешение шедулинга новых подов.
  - `Drain`: контролируемое вытеснение подов с ноды перед проведением техработ.
- **Rolling Reboot (`operations/service.go`)**:
  - Автоматизированная поочередная перезагрузка всего кластера или группы нод:
    1. Cordon & Drain ноды.
    2. Перезагрузка ноды через Talos API.
    3. Ожидание выхода ноды в статус `Ready` и стабилизации Kubelet.
    4. Uncordon ноды.
    5. Переход к следующей ноде без прерывания доступности кластера.

### 2.2. Сервисы и логи Talos Linux
- **Управление системными демонами**:
  - Просмотр статусов внутренних служб Talos (`machined`, `containerd`, `udevd`, `kubelet`, `trustd`, `timed`, `cri`).
  - Возможность перезапуска отдельных системных сервисов.
- **Потоковый просмотр логов (`streamer.go`)**:
  - Подключение к потоку логов ядра и любого сервиса Talos в реальном времени через gRPC streaming без необходимости наличия SSH на ноде.

### 2.3. Работа с конфигурацией (`MachineConfig`)
- Получение текущей активной конфигурации ноды (`talosctl get mc`).
- Валидация YAML-манифестов конфигурации перед применением.
- Применение патчей конфигурации на лету без полной переустановки ноды.

### 2.4. Автоматическое масштабирование и провижининг воркеров (`internal/proxmox`, `installer.go`)
- Прямая интеграция с гипервизором Proxmox VE.
- Мастер добавления воркера:
  - Генерация конфигурации ноды с валидацией имени по RFC 1123.
  - Клонирование/создание ВМ в Proxmox с нужным количеством ядер и RAM.
  - Автоматическая передача `talosconfig` и добавление новой ноды в кластер.

### 2.5. Бэкапы и восстановление (`internal/backup`)
- Создание etcd-снапшотов кластера по расписанию и по требованию.
- Сохранение архивов машинных конфигураций.
- Управление точками восстановления и скачивание резервных копий через UI.

### 2.6. Система алертинга и уведомлений (`internal/alerts`)
- Фоновый мониторинг состояния компонентов кластера.
- Отправка уведомлений в **Telegram** (`telegram.go`):
  - Потеря связи с нодой (`NotReady`).
  - Деградация кворума etcd.
  - Критическая нехватка диска или памяти.
  - Успешное/неуспешное завершение фоновых задач обслуживания.

### 2.7. Менеджер фоновых задач (`internal/jobs`)
- Асинхронное выполнение долгих операций (Rolling Reboot, установка обновлений, бэкапы).
- Отслеживание шагов выполнения в реальном времени с выводом прогресс-бара и логов выполнения.

### 2.8. Мониторинг Kubernetes Workloads & Storage (`internal/k8s`)
- Просмотр запущенных подов, деплойментов и демосетов.
- Мониторинг хранилищ: состояние PersistentVolumes и PersistentVolumeClaims (связка томов `local-path` с подами).

### 2.9. Безопасность и Аудит (`internal/audit`, `internal/auth`)
- Журналирование всех действий пользователей в аудит-лог (кто, когда и какую операцию выполнил).
- Защита эндпоинтов, поддержка авторизации по токенам и OIDC/Keycloak.

## 3. Пользовательский интерфейс (Frontend)

Фронтенд построен по принципу интерактивной панели управления (SPA) с быстрой навигацией:

| Раздел UI | Компонент | Возможности |
|---|---|---|
| **Главный дашборд** | `DashboardView.vue`, `ClusterStats.vue`, `HealthPanel.vue` | Общие метрики кластера (CPU, RAM, диски), статус здоровья etcd, apiserver, kubelet, flannel. |
| **Ноды кластера** | `NodesView.vue`, `NodeCard.vue`, `NodeInspector.vue` | Список и карточки нод, аппаратные ресурсы, роли, статус готовности, быстрый переход к управлению. |
| **Конфигурация нод** | `MachineConfigView.vue` | Просмотр YAML конфигурации ноды с подсветкой синтаксиса, защитой от горизонтального скролла, валидация. |
| **Центр операций** | `OperationsView.vue` | Запуск одиночного ребута, Rolling Reboot всего кластера, включение/выключение Maintenance Mode (Drain/Cordon). |
| **Добавление воркера** | `AddWorkerModal.vue` | Модальное окно создания воркера с валидацией имени ноды по RFC 1123, настройкой параметров ВМ Proxmox. |
| **Логи сервисов** | `LogsModal.vue` | Терминальное модальное окно с потоковым чтением логов любого демона Talos в реальном времени. |
| **Службы Talos** | `ServicesModal.vue` | Детальный список внутренних служб ноды, статус демонов и кнопка безопасного рестарта службы. |
| **Воркстейты K8s** | `WorkloadsView.vue` | Обзор пространств имен, деплойментов, подов и рестартов контейнеров. |
| **Хранилище** | `StorageView.vue` | Аналитика PersistentVolumeClaims и дисковых томов `local-path`. |
| **Фоновые задачи** | `JobsView.vue` | Журнал выполнения асинхронных операций (Rolling Reboot, резервное копирование). |

### UX и эргономика интерфейса:
- **Body Scroll Lock**: блокировка прокрутки страницы при открытии любых модальных окон.
- **Закрытие по клавише Escape** и клику вне области модального окна (backdrop click).
- **Интернационализация (i18n)**: полная поддержка переключения языков (Русский / English).
- **Обработка граничных состояний**: понятные предупреждения (Empty State) при временной недоступности нод вместо ложных сообщений об отсутствии фильтров.
- **Адаптивность**: поддержка экранов ноутбуков и мониторов высокой плотности, усечение длинных FQDN-хостнеймов без поломки верстки.

## 4. API Endpoints бэкенда

| Метод | Эндпоинт | Назначение |
|---|---|---|
| `GET` | `/healthz` | Liveness-проба для K8s (200 OK при живом процессе) |
| `GET` | `/readyz` | Readiness-проба для K8s (проверка gRPC mTLS связности с нодами) |
| `GET` | `/api/nodes` | Список всех нод с метриками ресурсов и статусами |
| `GET` | `/api/nodes/:id` | Детальная информация по конкретной ноде |
| `GET` | `/api/nodes/:id/services` | Список сервисов ноды (containerd, machined, etc.) |
| `POST`| `/api/nodes/:id/services/:svc/restart` | Перезапуск указанного сервиса |
| `GET` | `/api/nodes/:id/logs` | Потоковые логи выбранного сервиса |
| `GET` | `/api/nodes/:id/config` | Текущая машинная конфигурация (YAML) |
| `POST`| `/api/nodes/:id/reboot` | Перезагрузка ноды |
| `POST`| `/api/nodes/:id/maintenance` | Включение/выключение режима обслуживания |
| `POST`| `/api/operations/rolling-reboot` | Запуск процесса Rolling Reboot кластера |
| `GET` | `/api/operations/jobs` | Список фоновых задач и их статусов |
| `GET` | `/api/backups` | Список созданных резервных копий etcd |
| `POST`| `/api/backups` | Создание новой резервной копии |
| `POST`| `/api/proxmox/create-worker` | Заказ новой виртуальной машины воркера в Proxmox |
| `GET` | `/api/k8s/workloads` | Список подов и нагрузок Kubernetes |
| `GET` | `/api/k8s/storage` | Состояние PVC и хранилищ |
| `GET` | `/api/audit` | Журнал аудита действий администраторов |
| `POST`| `/api/auth/login` | Аутентификация пользователя |

## 5. Доставка и развертывание в кластере

1. **Контейнеризация (`Dockerfile`)**:
   - Многоэтапная сборка:
     - `Stage 1 (Bun)`: компиляция Vue 3 фронтенда.
     - `Stage 2 (Go)`: статическая сборка Go-бинарника с внедрением собранного фронтенда (`go:embed`).
     - `Stage 3 (Alpine)`: ультра-минималистичный runtime-образ (весит ~35 МБ), запускающийся под пользователем `talosdeck:talosdeck` (UID 1000).
2. **Kubernetes манифесты (`gitops/talosdeck/`)**:
   - `deployment.yaml`: содержит запросы и лимиты ресурсов (CPU: 50m-500m, RAM: 64Mi-256Mi), пробы `/healthz` и `/readyz`, монтирование томов `talosdeck-data` и секретов `talosdeck-config`.
   - `service.yaml`: ClusterIP (порт 8080).
   - `pvc.yaml`: PersistentVolumeClaim на 20 GiB через StorageClass `local-path`.
   - `kustomization.yaml`: декларативное управление версией образа из GHCR.
3. **Автоматизация**:
   - Любой коммит в ветку `main` запускает пайплайн GitLab CI: сборка через **Kaniko**, пуш в **GHCR** и автокоммит обновленного хеша образа в GitOps-репозиторий для **Argo CD**.
