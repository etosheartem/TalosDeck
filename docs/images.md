# Образы Talos Image Factory

TalosDeck поддерживает официальный Image Factory, платформу `metal`, архитектуру `amd64` и stable Talos versions. Профиль выбирает только официальные extensions из каталога целевой версии. Kernel arguments, META, overlays, owner и встроенные MachineConfig не принимаются: в профиле нет места для credentials.

Версии и каталоги доступны через [официальный Factory API](https://github.com/siderolabs/image-factory/blob/main/docs/api.md). Read-каталог кэшируется на пять минут, максимум 32 записи; при ошибке обновления ранее проверенный каталог может вернуться с `stale=true` и исходным `checkedAt`. Создание и разрешение профиля требуют свежих каталогов и завершаются ошибкой при недоступности Factory.

Schematic ID — SHA256 канонического YAML. Клиент проверяет полученный schematic повторно и сверяет его канонический hash с ID, используя формат сериализации upstream. Профиль фиксирует version, schematic, список extension refs/digests, installer image и ISO URL. Имена выбранных extensions дедуплицируются и сортируются при создании. [Описание schematics](https://docs.siderolabs.com/talos/v1.12/learn-more/image-factory).

Boot ISO и installer должны использовать один schematic и версию. Для Proxmox нужен `siderolabs/qemu-guest-agent`. Смена extension требует установки нового образа; профиль не включает extension на работающей ноде без upgrade. Поддержка extension проверяется заново для целевой версии.

Для проверки ISO используется потоковый SHA256 канонического asset из Factory, без загрузки образа целиком в память. Лимит — 2 GiB и десять минут. Переданный извне `isoURL` игнорируется: адрес строится из проверенных ID/version/platform/architecture. Разрешены не более трёх redirects внутри Factory origin либо на фиксированный HTTPS `assets.factory.talos.dev` (порт 443). Произвольные CDN не считаются доверенными. При живой проверке HEAD отвечал HTTP200 с Factory, а GET перенаправлялся на этот официальный asset hostname.

Этот hash обеспечивает соответствие скачанного ISO проверенному asset. Он не заменяет независимую проверку подписи: доверие к первичной загрузке опирается на проверенный HTTPS Factory. При обрыве загрузки или превышении лимита checksum не выдаётся. Большая загрузка выполняется в фоне через provisioning job, а не при открытии списка образов.

Запросы каталогов ограничены двадцатью секундами и ответом 2 MiB; одновременно выполняется не более четырёх запросов. В API нет пользовательского Factory URL или произвольных download endpoints.

В инспекторе ноды вкладка расширений показывает фактический schematic и версии
установленных extensions. Проверка целевой версии сообщает доступность этого
набора в Factory; она не заменяет preflight обновления всего кластера.
Пустой настроенный installer или его расхождение с работающим образом видны
отдельно и требуют проверки MachineConfig. TalosDeck не подставляет repository
на основании догадки. Инвентаризация не доказывает отсутствие staged changes:
необходимость перезагрузки для них может оставаться неизвестной.
